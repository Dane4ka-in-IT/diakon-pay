# 💸 DiakonPay — Offline-First PWA для управления личными финансами

**DiakonPay** — это MVP-версия прогрессивного веб-приложения (PWA) для удобного трекинга доходов и расходов. Главная особенность системы — **полноценная работа в офлайн-режиме** с последующей пакетной синхронизацией данных при появлении сети. 

Проект разработан в рамках командной работы на базе МАИ (кейс от компании «Т1»).

---

## 📑 О проекте
Цель проекта — создание отказоустойчивой системы учета личных финансов, независимой от качества интернет-соединения. Архитектура спроектирована по методологии **C4**. Backend-часть предоставляет надежный REST API, обеспечивает транзакционную целостность, мгновенную обработку сессий и асинхронную рассылку HTML-уведомлений.

---

## 🛠 Стек технологий

### Backend (Ядро)
* **Язык и фреймворк:** Java 17, Spring Boot 3
* **Безопасность:** Spring Security, JWT (Access / Refresh токены), BCrypt
* **Рассылка писем:** `spring-boot-starter-mail`, **Thymeleaf** (генерация HTML-шаблонов)
* **API и Тестирование:** REST API (27 эндпоинтов), Swagger UI

### Базы данных
* **PostgreSQL (Основная СУБД):** Хранение персистентных данных, PL/pgSQL-триггеры, View для аналитики.
* **Tarantool (In-memory СУБД):** Быстрое хранение сессий, кэширование, логика инвалидации токенов, Lua-скрипты.
* **IndexedDB (Локальная СУБД):** Браузерное хранилище для работы PWA в offline-режиме.

### Frontend
* **Технологии:** TypeScript, React
* **Архитектура:** PWA (Service Worker)

### Инфраструктура и управление
* **Среда разработки:** Экосистема «Сфера» (Сфера.Задачи, Сфера.Знания, Сфера.Код)
* **Методология:** Scrum (5 спринтов)

## ✨ Ключевые особенности и архитектурные решения

### 1. Offline-First и синхронизация
* **UUID-идентификация:** Ключи для транзакций, счетов и категорий генерируются на стороне клиента (PWA). Это исключает коллизии при выгрузке данных в PostgreSQL.
* **Пакетная отправка:** Алгоритм `syncTransactions` обрабатывает массив транзакций, накопленных без сети. При ошибке в одной записи (статус `FAILED`), остальные успешно сохраняются, а клиенту возвращается статус `PARTIAL`.
* **Локальный кэш:** IndexedDB хранит очередь сообщений (`pending_transactions`) и справочники для автономного создания операций.

### 2. Продвинутая бизнес-логика и БД
* **Оптимизация аналитики:** Агрегация финансовых показателей (сумма доходов/расходов) вынесена на уровень PostgreSQL (аннотации `@Query`, `GROUP BY`, представления). Тип данных — `BigDecimal`.
* **Soft Delete:** Счета не удаляются физически (флаг `isDeleted`), что сохраняет ссылочную целостность для исторической аналитики.
* **Категории:** Гибридная модель. Пользователям доступны базовые (системные) категории с возможностью добавления пользовательских.

### 3. Производительность и Безопасность (JWT + Tarantool)
* Реализована авторизация на базе **JWT**.
* Интегрирована In-memory СУБД **Tarantool** для управления сессиями.
* Написаны скрипты на **Lua** для инициализации пространств с hash- и tree-индексами.
* Реализована проверка времени жизни (TTL) для OTP-кодов и блокировка (Blacklist) отозванных токенов при выходе (Logout).

### 4. Асинхронные уведомления (SMTP + Thymeleaf)
* Независимый сервис `SMTPService` с аннотацией `@Async` (отправка писем не блокирует основной API).
* Использование **Thymeleaf** для генерации красивых HTML-писем с динамическими переменными.
* **Функционал:** Автоматические приветственные письма, отправка одноразовых кодов (OTP) для восстановления пароля или безопасной смены Email.

## 🗄 Структура баз данных
* **PostgreSQL (3НФ):** Гибридная стратегия идентификации (UUID для транзакций/счетов, Integer для системных логов). Содержит таблицы: `Users`, `Accounts`, `Categories`, `Transactions`, `Audit_logs`.
* **Tarantool:** Пространства для хранения активных refresh-сессий и временных OTP-кодов.
* **IndexedDB (Проекция):** Таблицы `pending_transactions`, `cached_accounts`, `cached_categories`, `cached_analytics`.
